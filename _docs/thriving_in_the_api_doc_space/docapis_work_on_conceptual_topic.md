This part of the activity might be challenging, but here is where you'll start building some examples for your portfolio. Use the same open-source project that you found in [Activity: Find an open-source project with API doc needs](docapis_find_open_source_project.html).

{% include image_ad_right.html %}

1.  In the project, identify one of the API reference topics that needs help. (If the API has a new reference endpoint to document, focus on this endpoint.)
2.  Read the project's contribution guidelines, usually in a `CONTRIBUTING.md` file at the root of the repository. Some projects want you to open or comment on an issue before you submit changes, so that maintainers know what you're working on.
3.  Edit the topic to improve it. (If it's a new endpoint, write the documentation for it.) Use the reference sections described in [Documenting API endpoints](docendpoints.html) as a checklist: resource description, endpoints and methods, parameters, request example, and response example.
4.  Test any requests or code samples in the topic against the API, so that you know they work.
5.  Create a [pull request](pubapis_github_pull_requests.html) and contribute your edits to the project. Respond to any review comments from the maintainers.
6.  After your pull request is merged, add a link to it in your portfolio. A merged pull request shows employers that a real project accepted your documentation.
